# Build and deploy from the command line (xtool + Xcode)

One script runs the whole pipeline: `scripts/deploy-xtool.sh`. Every command takes `--dry-run`,
which prints what would run and changes nothing.

| Command | Tool | Needs |
|---|---|---|
| `doctor` | — | nothing; reports tools, simulator runtimes, xtool login, which ASC variables are set |
| `setup` | xtool | nothing; tells you whether `xtool auth login` is still owed |
| `sim [--udid ID]` | **xtool** | nothing; builds, installs and launches on a simulator |
| `device [--udid ID]` | **xtool** | `xtool auth login` (once) + iPhone on USB or the same Wi-Fi |
| `archive --unsigned` | Xcode | nothing; proves the Release archive builds, touches no account |
| `archive` | Xcode | Xcode signed in to team `477WWCHXU7`, or the ASC key below |
| `validate` | Xcode (`altool`) | ASC key |
| `upload --confirm-upload` | Xcode (`altool`) | ASC key **and** `YAHPAZ_ALLOW_UPLOAD=1` |

## Why two tools

xtool (1.22.2, `brew install xtool-org/tap/xtool`) builds **SwiftPM packages** into iOS apps,
signs them with a development profile, and installs them on a simulator or a device. It has no
App Store distribution signing and no upload command, so it cannot produce or send a store build.

So the split is:

- **Dev builds → xtool.** `xtool/` is a SwiftPM wrapper around the existing app: `xtool/Package.swift`
  declares one library whose sources are `App/` (symlink `xtool/Sources/YahpazApp → ../../App`), and
  `xtool/xtool.yml` lists what goes at the bundle root. Nothing in `App/` or the Xcode project
  changed shape for this.
- **App Store → Xcode.** `archive` runs `xcodebuild archive` + `-exportArchive` against
  `Yahpaz.xcodeproj` (generated by xcodegen from `project.yml`), `validate` and `upload` run
  `xcrun altool` with an App Store Connect API key.

## What the script does around xtool

xtool merges a partial `Info.plist` and copies root resources, but three things need help. The
script does them before every xtool build, into `xtool/.generated/` (git-ignored):

1. **Info.plist.** `App/Info.plist` uses Xcode build variables (`$(EXECUTABLE_NAME)`,
   `$(CURRENT_PROJECT_VERSION)`). The script copies it, drops the keys xtool owns, pins
   `CFBundleVersion` from `project.yml`, and sets `UIDeviceFamily` to iPhone only.
2. **Asset catalog.** SwiftPM does not compile `Assets.xcassets` into the app bundle, so the
   script runs `actool` and xtool copies the resulting `Assets.car` (WhatsApp mark, accent and
   launch colours). The icon comes from `iconPath`.
3. **Package pins.** `Package.resolved` is copied from the Xcode project so both builds use the
   same supabase-swift and swift-crypto versions.

### xtool bug the script works around

xtool 1.22.2 plans a resource bundle for every target that declares resources, including
targets that SwiftPM only builds on Linux. swift-crypto puts its `CXKCPShims`, `CCryptoBoringSSL`,
`CCryptoBoringSSLShims` and `CryptoBoringWrapper` targets behind a platform condition, so Swift
Build never produces their bundles on Apple platforms and packing fails with
`The file "swift-crypto_CXKCPShims.bundle" couldn't be opened`. The script reads the missing bundle
name from the error, drops an empty placeholder bundle in its place, and retries (four
placeholders today). The placeholders hold nothing the app reads. Worth an upstream issue on
`xtool-org/xtool`; until then the workaround is automatic.

## Device builds with xtool

`device` needs xtool signed in once, interactively:

```bash
xtool auth login        # choose "API Key" — see "App Store Connect API key" below
```

xtool installs under a team-prefixed bundle ID (`XTL-…com.yahpz.responder`), so the dev build sits
**beside** the Ad Hoc / App Store app instead of replacing it. Push notifications are not set up on
that ID, so pushes reach only the real build.

## App Store Connect API key (Omri's step)

Created once in App Store Connect → Users and Access → Integrations → Team Keys, role
**App Manager**. Download the `.p8` (Apple shows it once) and keep it **outside the repo**, for
example `~/.appstoreconnect/private_keys/AuthKey_<KEYID>.p8`. Then, in your shell only:

```bash
export ASC_KEY_ID=<key id>
export ASC_ISSUER_ID=<issuer id>
export ASC_KEY_PATH=~/.appstoreconnect/private_keys/AuthKey_<KEYID>.p8
```

The script never prints these values: dry runs show `"$ASC_KEY_ID"`, and `ASC_KEY_PATH` inside the
repo is refused. `.gitignore` already ignores `*.p8` and `.env`.

## Store release, end to end

```bash
scripts/deploy-xtool.sh doctor
# bump CURRENT_PROJECT_VERSION (and MARKETING_VERSION if needed) in project.yml first
scripts/deploy-xtool.sh archive            # → dist/appstore/Yahpaz.ipa, nothing uploaded
scripts/deploy-xtool.sh validate           # App Store Connect checks the binary
YAHPAZ_ALLOW_UPLOAD=1 scripts/deploy-xtool.sh upload --confirm-upload
```

`archive` exports with `scripts/export-options-appstore-ipa.plist` (App Store signing, export only).
It does **not** use `export-options-local.plist`: that one sets `testFlightInternalTestingOnly`,
which App Review refuses. `upload-testflight.sh` (Xcode upload in one step) still works and is
unchanged.

The Ad Hoc path (`build-adhoc.sh`, `publish-ios.sh`) is untouched.
